## What KinetoFun Is

KinetoFun is a **gesture-based gaming platform for TV**. It runs initially as a **web-first** system and will later add hardware (Raspberry Pi + camera + MediaPipe gesture tracking) as an input layer.

Users will be able to:
- Connect to KinetoFun from a TV (web interface)
- Navigate using keyboard/mouse initially (gesture input comes later)
- Browse and launch games
- Play multiplayer or single-player games
- Save scores and track progress
- Use a future gesture-based input system (MediaPipe + Raspberry Pi)
- Optionally purchase access (paywall system, later)

## Current System Architecture

- **Frontend:** Next.js 16.2.7 (App Router) + React 19, TypeScript 5, Tailwind CSS v4, ESLint 9. `src/` dir, `@/*` import alias. (web-first, TV-oriented UI)
- **Backend:** Custom Next.js Route Handlers (`/api/auth/*`) + **Supabase PostgreSQL — LIVE** (database only, **no Supabase Auth**) via the `@supabase/supabase-js` client (`src/lib/supabase/server.ts`, service-role, server-only) behind a swappable repository. Falls back to a local file store only if env is unset. Full schema in `supabase/schema.sql`.
- **⚠️ Runtime needs the system CA:** this machine intercepts TLS, so Node must run with `--use-system-ca` to reach Supabase. Baked into the `dev`/`build`/`start` npm scripts via `cross-env` (ADR-007/ADR-014). Credentials live in `.env.local` (git-ignored).
- **Auth:** **Custom JWT auth — implemented + hardened.** scrypt-hashed passwords, HS256 JWT (via `jose`) in an httpOnly cookie, `proxy.ts` route protection, server-side DAL. **Hardened (ADR-019):** rate limiting on `/api/auth/*` and revocable sessions (`sid` claim + `auth_sessions` rows checked in the DAL; logout + "sign out everywhere" truly invalidate). See ADR-013 + ADR-019.
- **⚠️ Next.js 16 conventions (this is a customized v16):** `middleware.ts` → **`proxy.ts`** (function `proxy`, Node.js runtime only); `cookies()`/`params`/`searchParams` are **async**; Turbopack is the default. Always read `node_modules/next/dist/docs/` before writing framework code (per AGENTS.md).
- **Input (current):** Keyboard / mouse
- **Input (future):** Raspberry Pi + camera + MediaPipe hand tracking
- **Runtime:** Node v24.16.0
- **VCS:** Git initialized — `main` (stable, tracking files only) and `dev` (active, scaffold). Currently on `dev`.

> Phase 1 frontend is complete: a full TV-style gaming portal UI driven entirely by mock data. `npm run build` passes; all routes return 200.

## Completed Features

- **[2026-07-03] Zoo & Aquarium Architect (ADR-048).** Gesture-only creative zoo-building sim — the fourteenth game and the third to reuse the persistent-sim + pinch-drag architecture from Farm Builder/Pocket Pal, deliberately returning to that proven template after Circuit Racer's rocky first pass. Unlock 4 zones in order with Tickets (Savanna free-starter, Arctic 40, Ocean/Aquarium 90, Rainforest 160), then pinch-drag ~28 unlockable animals/decorations from a shop tray onto the active zone's canvas at **any free-form position** (not a grid, not a single fixed dropzone — the one genuinely new mechanic, built as a small extension of the existing `usePinchDrag` hook using its already-exposed `cursorPx` + the canvas's bounding rect to compute zone-relative fractional coordinates, no hook changes needed). Every placed item contributes an appeal value; visitors generate Tickets passively over real time based on total appeal (uncapped timestamp-accrual formula, same pattern as farm-builder's crop growth / pocket-pal's stat decay but without a [0,1] ceiling, matching the family's "currency only goes up" rule); a dwell "Collect Tickets" button banks the accrued amount. No fail state: nothing decays, nothing can be placed wrong, appeal only increases. 6 achievements (First Habitat, Zoologist, Zone Master, World Traveler, Ticket Tycoon, Master Architect). Score submitted on exit is lifetime total Tickets earned (monotonic), same `public.scores` table as every game. **Verification note:** given Circuit Racer's lesson that a clean build doesn't guarantee working logic, this game's actual store logic was runtime-verified before shipping — a temporary Node/tsx script exercised `useZooStore`'s real actions (unlock gating, placement gating, zone-chain ordering, all 6 achievement thresholds, ticket-accrual arithmetic) and all 25 assertions passed, plus a headless-Chromium pass confirmed zero console errors through calibration/menu screens. Built Vite game (421KB JS gzipped), served from `public/games/zoo-architect/`. Registered in `src/games/registry.ts`. Seed SQL: `supabase/seed_zoo_architect.sql` (Adventure category, published, featured, age_group `4-9`, difficulty `easy`). No camera in this environment — pinch-drag remains untested against a live hand, same standing caveat as every pinch-drag game.
- **[2026-07-03] Circuit Racer (ADR-047).** Gesture-only multi-course racing sim — the thirteenth game and first racing game in the catalog. 6 courses (3–5 laps, progressively harder AI), linear unlock (beat course N in top-3 to unlock N+1), position-based coin scoring (1st=3, 2nd=2, 3rd=1, 4th=0), no fail state (a hover-dwell "Quit Race" button always lets the player leave without penalty). Gesture controls: hand-X steers, raise hand accelerates, lower hand brakes, fist boosts. Three AI opponents race a closed-loop stadium track simultaneously; race ends the instant the player finishes, rank computed from how many AI had already finished by then. Lifetime coins earned (monotonic) submitted as score. **The first implementation pass shipped as a non-functional placeholder** — `RaceScreen.tsx` was a fake `setInterval` that declared "1st place" after 3 seconds over a blank canvas; the user caught this immediately. Rebuilt for real: **physics** is a simple arcade top-down kinematic model (`game/carKinematics.ts`, position+heading+speed integrated each frame) — NOT the Matter.js suspension rig originally planned to fork from gesture-hill-adventure, since that model is side-view-only (vertical spring wheels, no steering axis) and doesn't apply to a top-down racer. **Track** is a procedural stadium loop (`game/track.ts`, two straights + two semicircle turns as an ordered waypoint array). **AI** is waypoint-follow pure pursuit (`game/aiRacer.ts`) with per-car speed variance. **Rendering** is a fixed top-down camera centered on the player (not the mob-rally trapezoid projection originally planned — simpler and more reliably testable without a live camera); HUD drawn directly on canvas each frame (not React state) to stay at 60fps. A standalone Node/tsx simulation of the real physics+AI+lap-tracker pipeline (temporary script, deleted after use) caught two real bugs before shipping: (1) proximity-based lap detection re-triggered every frame a car dwelled near the finish point, and (2) even after fixing that, cars spawning on the tight 4-car starting grid could drift through the finish-zone radius and falsely register a lap in 0.4s, before doing any real lap — fixed by switching lap detection entirely to waypoint-index wraparound (a lap only counts when a car's nearest-waypoint index jumps from the far end of the track back to the near end, which incidental grid drift can't produce). The same simulation then revealed the AI recorded zero laps due to a geometry bug: the semicircle-turn waypoint math didn't connect to the preceding straight's endpoint, creating a ~1000px teleport at each straight→curve boundary that sent AI cars (which commit to one target until arrival) into a spin; fixed the angle math. Verified via the simulation script (realistic ~14s laps, correct difficulty scaling, correct finish-order-to-coins mapping) and a headless-Chromium pass (zero console errors through calibration/menu). Built Vite game (419KB JS gzipped), served from `public/games/circuit-racer/`. Registered in `src/games/registry.ts`. Seed SQL: `supabase/seed_circuit_racer.sql` (Sports category, published, featured, age_group `5-9`, difficulty `medium`). **Known limitations:** all 6 courses share one track shape (only lap count/AI speed differ; per-course track variety unbuilt); no wall/boundary collision; gesture thresholds unverified against a live camera; achievements not yet wired up.
- **[2026-07-03] Pocket Pal (ADR-046).** Gesture-only virtual pet companion game — the twelfth game overall and the *second* persistent-state sim after Little Farm Builder, proving the real-time growth-from-timestamp infrastructure is generic enough to support multiple game domains beyond farming. A single fixed companion (emoji-based, no species picker in v1) with two stats — **Hunger** and **Happiness** — deliberately two, not three; the family has never asked kids to juggle more than two core mechanics at once. Unlike Farm Builder's economy-driven progression, Pocket Pal's growth is **relational and stage-driven:** a separately-tracked, always-forward **Growth Stage** (Baby → Child → Teen → Adult → Elder) driven by lifetime care-action count (monotonic, like farm-builder's achievement counters), not by stat management. No fail state ever — both stats have a floor of 40/100, so the pet never "dies" or enters a game-over state even if totally neglected for days; it just looks mildly sad (💧 badge + droopy animation) and perks back up the instant the player interacts, matching the no-punishment philosophy of every KinetoFun game. Stat decay reuses farm-builder's `getGrowthFraction` helper (`game/growth.ts` copied unchanged): a persisted (value, lastTickAt) pair is recomputed on load by comparing `lastTickAt` against `Date.now()` rather than using a running timer, so decay keeps happening even while the game is closed; Hunger decays to 40/100 over ~90 min, Happiness over ~180 min (guessed constants, flagged for real playtesting). Mood tiers derived from `min(hunger, happiness)`: **joyful** (both ≥80), **happy** (both ≥60), **okay** (the floor, never framed as sick/dying). Core interactions split between pinch-drag (Feed/Play, reusing `usePinchDrag` from ADR-045 unchanged) and hover-dwell (~700ms on the pet sprite to pet/pat it, earning +15 happiness). Nine unlockable care items split across 3 foods (Treat/Fruit/Veggies, costs 0/15/25 hearts, restore 40/50/55 hunger), 3 toys (Ball/Rope/Stick, costs 0/15/25 hearts, restore 40/50/55 happiness), and 3 cosmetic accessories (Hat/Bandana/Glasses, costs 10 each, pure CSS overlays). Every successful Feed/Play/Pet earns +1 Heart (uncapped, no cooldown — rewards grind-free play); Hearts only buy cosmetics (no per-use cost, no fail state), so grinding is harmless. On exit, `GAME_COMPLETE` submits **lifetime total Hearts earned** (monotonic, like farm-builder's `totalCoinsEarned`) as the leaderboard score, preserving the max-score-per-user shape despite having no discrete sessions. 6 achievements: New Best Friend (first action), Best Buddy (50 actions), All Grown Up (reach elder), Full Closet (all 9 unlocks), Heart of Gold (100 hearts lifetime), Picture Perfect (both stats at 100 simultaneously). New `stores/petStore.ts` — zustand + `persist` → localStorage, same mechanism as all games, new data shape: `{ hunger, happiness, lastHungerTickAt, lastHappinessTickAt, hearts, totalHeartsEarned, totalCareActions, unlockedItemIds, equippedAccessories, achievements }`. No DB schema changes — same generic `public.scores` table already used by all games; only lifetime total Hearts submitted per exit. New `game/petStats.ts` derives { hunger, happiness, mood, growthStage } from persisted state + current time, using `getGrowthFraction` to compute decay and rescaling onto the [40,100] floor range. `components/game/{PetScreen,PetSprite,CareTray}.tsx` own the pet sprite (scaled by growth stage), mood overlay (💧 bounce animation for "okay" mood), stat bars, and care tray (food/toy tiles + inline unlock buttons via `HoverButton` dwell). `tsc --noEmit` + `vite build` clean after stripping leftover farm-builder scaffolding. Dist served from `public/games/pocket-pal/`. Registered in `src/games/registry.ts`. DB seed: `supabase/seed_pocket_pal.sql` (Adventure category, published, featured, age_group `4-9`, difficulty `easy`). Caveat: pinch-drag has never been exercised against a live hand in this environment (no camera) — a webcam pass is strongly recommended before shipping, doubly so since this game reuses the same primitive for *both* core verbs (Feed and Play); the pinch-drag interaction is the highest-risk untested piece from farm-builder plus the decay-window constants (90/180 min) are guesses, not verifiable headless, flagged for real playtesting.
- **[2026-07-03] Little Farm Builder (ADR-045).** Gesture-only farming simulation, the eleventh game and a deliberate complexity step-up from the prior ten session-based match/sort games (user explicitly asked for "something more complex"). First game with a **persistent, evolving save state**: a farm that keeps growing in real time between visits (not a per-session best score), and the first to use **continuous pinch-and-drag** as its core interaction instead of hover-and-dwell. Core loop: pinch-grab a seed from the tray, drag it onto an empty plot, release to plant (costs coins); crops grow through seed → sprout → ripe visual stages based on real elapsed wall-clock time — `game/growth.ts`'s `getGrowthFraction` compares a persisted `plantedAt` timestamp against `Date.now()`, so a crop keeps maturing even while the game is closed and the player returns later to a grown farm. Once ripe, pinch-grab the crop out of its plot and drag it to the basket to harvest for coins. Four crops with escalating pace/value (Carrot 20s/cheap/unlocked-from-start, Tomato 60s, Corn 3min, Pumpkin 8min/priciest) plus a 4-to-12 expandable plot grid, both gated behind coin costs unlocked via ordinary `HoverButton` dwell — deliberately, only planting/harvesting use the new pinch-drag mechanic, keeping the shop/expansion economy on the already-proven dwell pattern. New gesture primitive: `HandFrame` gains `isPinching` (thumb-tip-to-index-tip distance < 0.07 normalized units, `mediaPipe/handTrackingCore.ts`) — same threshold already proven in `games/gesture-love-balls`'s pinch-to-draw mechanic, reused rather than re-derived. Since raw `isPinching` is jitter-prone near the threshold (unsmoothed, like `isFist`/`isPalmOpen`), new `hooks/usePinchDrag.ts` adds a 100ms sustain-before-grab debounce (`PINCH_CONFIRM_MS`) — again mirroring gesture-love-balls' fix for the identical noise problem — while keeping release instant so letting go feels responsive. `usePinchDrag` extends `HoverButton`'s existing DOM-rect hit-testing idiom (`getBoundingClientRect()` vs. `cursorX/Y * window.innerWidth/innerHeight`) to a grab/carry/drop flow rather than building a canvas-based drag engine; grabbable/dropzone rects are computed lazily only at the instant a pinch starts/ends, not every frame. `FarmScreen.tsx` owns all the plot/tray/basket DOM refs directly (no context/registry indirection), matching how every other game's top-level `GameplayScreen` owns round state directly. New persistence shape in `stores/farmStore.ts` — still zustand + `persist` → localStorage (same mechanism as every other game's `progressStore.ts`), but a new data shape: `coins` (spendable), `totalCoinsEarned` (lifetime monotonic — this is what gets submitted to `public.scores` on exit, since it only ever grows, preserving the platform's max-score-per-user leaderboard semantics despite there being no discrete rounds), `totalHarvests`, `unlockedCropIds`, `unlockedPlotCount`, and a 12-slot `plots` array. No DB schema changes — `public.scores` stays the same generic `(game_id, user_id, score, achieved_at)` table every other game already uses; the farm's real state stays client-side only. No fail state: coins only go up, plots only unlock, matching the no-punishment philosophy of every other KinetoFun game. 6 achievements (First Harvest, Green Thumb, Full Table, Land Baron, Century Farmer, Master Grower). `tsc --noEmit` + `vite build` clean on the first pass. Dist served from `public/games/farm-builder/`. Registered in `src/games/registry.ts`. DB seed: `supabase/seed_farm_builder.sql` (Adventure category — no existing category fits a persistent building sim better than the 6 available; published, featured, age_group `4-9`, difficulty `easy`). **Highest-risk untested piece of any game in this family so far:** the pinch-drag mechanic has never been exercised against a live hand in this build environment (no camera here) — is the 100ms confirm responsive, is the 0.07 pinch threshold comfortable at typical webcam distance, does the held-item ghost track cleanly? A webcam pass is strongly recommended before shipping, more so than for any prior game.

- **[2026-07-02] Musical Instrument Sounds (ADR-043).** Gesture-only sound-recognition game, the ninth in the small-and-simple family and the **first with an audio-first prompt**: every prior game narrates a visual prompt as an *optional* accessibility layer, but here the prompt itself has no visual content at all — the player must listen to a synthesized instrument sound and then pick the matching instrument visually. Each round plays a short (~0.2-0.6s) procedurally synthesized sound (`audio/instruments.ts`, new); the player hovers the bin showing the matching instrument icon + name among 2-4 distractors. A **Replay** `HoverButton` lets the child re-trigger the prompt sound as many times as needed — necessary since, unlike a visual prompt that stays on screen, an audio cue can be missed or forgotten mid-round; `PromptDisplay.tsx` also auto-plays once on round start. Modes split by instrument family, the same content-grouping shape as Alphabet Zoo's `letter`/`animal`/`mixed` and Opposites Match's `word`/`picture`/`mixed`: **Percussion** (drum, tambourine, xylophone, cymbal, maracas), **Melodic** (piano, guitar, flute, violin, trumpet), **Mixed** (all ten). New `noiseBurst()` synthesis helper (randomized `AudioBuffer` through a highpass/bandpass `BiquadFilterNode`) sits alongside the existing `tone()` oscillator-envelope pattern from `audio/sound.ts`; `sound.ts` gained two small new exports (`getAudioContext()`, `getSfxVolume()`) so `instruments.ts` shares the same `AudioContext`/volume rather than opening a second one — the first cross-module audio dependency in the game family. Types follow Opposites Match's flat-id pattern: `BinDef`/`RoundPrompt` reference `instrumentId` directly rather than a scenario lookup, since distractors are drawn from a flat per-family pool. Scoring, achievements, settings, calibration, App shell all reused verbatim from Opposites Match — same `finalizeSession`/`RoundTally` logic, same 6-achievement pattern (First Round / Percussion Master / Melodic Master / Mixed Master / Perfect Round / Music Maestro), same 2-step calibration and `GAME_COMPLETE` postMessage contract. `tsc --noEmit` + `vite build` clean on the first pass. Dist served from `public/games/musical-instrument-sounds/`. Registered in `src/games/registry.ts`. - **[2026-07-02] Opposites Match (ADR-042).** Gesture-only vocabulary-building game, the eighth in the small-and-simple family, teaching opposite word pairs (big/small, hot/cold, fast/slow, up/down, happy/sad, day/night, open/closed, full/empty, tall/short, wet/dry, loud/quiet, heavy/light) — a new content domain not touched by any of the 7 prior games. Structurally closer to **Alphabet Zoo's** shape (ADR-036) than the Read/Set-style duality used by the last three games (Clock & Time Teller / Coin & Money Counter / Weather & Seasons Sorter): "opposite of" is a symmetric relation, so there's no natural A→B vs B→A split — instead the mode split is **presentation style**, like Alphabet Zoo's `letter`/`animal`/`mixed`: **Words** mode shows a text prompt + text-answer bins; **Pictures** mode shows an icon prompt + icon-answer bins (prompt and bins share the same presentation within a round, unlike the Read/Set games where they're opposite); **Mixed** randomly varies presentation per round. Which word of the pair is the prompt vs. correct answer is randomized independently of mode every round, so both directions of every pair get practiced regardless of mode. `data/opposites.ts` holds 12 pairs, each with a hand-drawn SVG icon per side (`OppositeIcon.tsx`, same no-image-assets style as `WeatherIcon`/`CoinIcon`/`ClockFace`). `distinctDistractorWords()` draws distractors from entirely different pairs (never the target pair's own two words), so a wrong choice is never a near-miss synonym. Types reshaped from the prior three games' scenario-id-lookup pattern: `BinDef` carries `{ word, glyph }` directly rather than a foreign key, since a bin's word can belong to any of the 11 non-target pairs (no single "canonical entry" the prompt and bin both reference). ### Key components
- **TopBar** — sticky nav (Home / Library / Leaderboard), live Clock, Settings, profile avatar or "Sign in".
- **SpatialNavigation** — global `keydown` handler; arrow keys move DOM focus to the nearest `[data-focusable]` element by geometry. This is the forward-looking primitive the gesture layer (Phase 4) will drive. Every interactive element carries `data-focusable`; focus ring styled in `globals.css`.
- **GameCard / GameRail** — gradient-cover tile + horizontal scrolling row (Netflix/console style). Width-flexible so the same card works in rails and the library grid.
- **Button / ButtonLink** — variants (primary/secondary/ghost/danger), sizes; `ButtonLink` wraps `next/link`.
- **LeaderboardTable, ScoreList, Avatar, StarRating, Badge, TextField** — presentational building blocks.

### State management
- **`SessionProvider` (`features/auth/session-context.tsx`)** — React Context, now **real**. On mount it calls `GET /api/auth/me` to restore the session from the httpOnly cookie (auto session-restore). Exposes `user`, `isAuthenticated`, `isLoading`, async `login`/`signup`/`logout`, and `refresh`. The JWT lives in a cookie (not `localStorage`), so there is no token in JS. Maps the canonical `AuthUser` onto the rich UI `User` via `toAppUser` (fills display/game defaults like level/xp/avatar until those are stored).
- **`ProtectedRoute`** — wraps auth-only pages (`/profile`, `/settings`); shows a loader during restore, then redirects unauthenticated users to `/login?next=…`. Belt-and-suspenders with `proxy.ts`.
- Page-local `useState` for search/filter/toggles. No global store needed yet.

- **`sessions.ts`** — `Session[]` play sessions (feeds "Continue playing" + recent activity).
- **`index.ts`** — re-exports all of the above.
